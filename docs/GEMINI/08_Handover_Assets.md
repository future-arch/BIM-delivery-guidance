# 第八章：竣工移交与资产信息采集 (Handover & Asset Data)

## 8.1 竣工交付的核心挑战：数据真实性与完整性

竣工移交是 BIM 数据生命周期的“临门一脚”。长期以来，这一环节最突出的问题是模型与现场严重脱节。本指南要求：

1. **几何真实性闭环**：数字化竣工模型（As-Built BIM）必须反映最终的现场物理状态，包括所有的设计变更、洽商及现场路由调整。

2. **逻辑资产化**：将“构件”转化为“资产（Assets）”。每个核心设备不仅要有 3D 形状，还要具备唯一的资产标签，并与实物粘贴的二维码/RFID 标签实现一一对应。

3. **静态与动态数据的剥离**：移交时应明确哪些是“静态属性”（如厂家、型号、安装日期）及“性能基准值”（如额定功率、设计流量），为运维阶段的动态数据接入提供基线。

## 8.2 数字化竣工模型 (As-Built BIM) 编制规则

竣工模型不能只是施工深化模型的拷贝，必须执行以下标准化操作：

### 8.2.1 模型精炼与去重

- **冗余数据清理**：剔除施工过程中的临时构件（如支模架、塔吊模型、临时堆场）。

- **层级合并**：在不损失语义的前提下，适当合并专业内的细碎模型，以提升运维端的加载效率。

### 8.2.2 关键资产属性补全

移交资产至少应包含以下特定字段（对应 **LOD 500** 思路）：
- **采购信息**：合同编号、供应商联系方式。

- **技术参数**：出厂日期、实测性能参数、合格证编号。

- **维保信息**：质保起止日期、维护周期建议、首批易损件清单。

## 8.3 资产信息核验与系统初始化交付

### 8.3.1 数字化资产核验 (Audit)

建设单位应组织监理或第三方机构，对竣工交付包进行“两审一核”：
1. **模型一致性抽检**：随机抽取不少于 5% 的典型区域，核对手持设备中的模型与现场物理实体的一致性。

2. **数据完整性自动审计**：利用脚本全量检查 IDP/EIR 所要求的关键属性填报率，未达到 100% 填报的交付包不予接收。

### 8.3.2 交付物与运维系统 (IWMS/FM) 的衔接

竣工交付成果应支持主流运维管理平台的初始化导入：

- **空间索引导出**：自动生成房间、区域与设备的拓扑关联表。

- **资产清单格式化**：输出符合 COBie (Construction Operations Building information exchange) 标准或自定义运维数据字典的结构化表格。

## 8.4 竣工移交清单

1. **最终版全专业数字化竣工模型 (As-Built IFC/Native)**。

2. **全生命周期设计变更与洽商索引数据库**。

3. **数字化资产台账总表**（含 GUID 与 资产 ID 映射）。

4. **隐蔽工程数字化影像记录关联包**。
