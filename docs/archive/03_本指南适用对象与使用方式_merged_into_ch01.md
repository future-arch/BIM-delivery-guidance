# 第3章 本指南适用对象与使用方式

## 3.1 本章目标

本章解决三个使用问题：

1. 哪些角色应当使用本指南。  
2. 不同角色应优先阅读哪些内容。  
3. 项目团队如何把本指南转化为日常执行动作。

本章定位为“使用说明”，不重复后续章节的技术细节。

## 3.2 适用对象

本指南主要适用于以下角色：

1. 建设单位（含项目管理团队）：用于明确交付目标、接收要求和节点要求。  
2. 设计单位：用于组织设计阶段信息生产与阶段性交付。  
3. 施工单位（含专业分包）：用于施工准备、施工过程信息更新和阶段移交。  
4. 竣工移交管理人员：用于组织交付成果核对与移交实施。  
5. 运维接收单位：用于前置提出接收条件并验证可用性。  
6. 信息管理岗位：用于维护命名、版本、检查与发布规则。  
7. 软件实施与开发团队：用于理解交付逻辑并落实数据结构与接口实现。

## 3.3 使用原则

1. 先按业务用途阅读，再按技术专题深化。  
2. 先完成本章定义的使用动作，再进入后续方法章节。  
3. 以项目节点为节奏更新执行文件，不一次性做完后长期不维护。  
4. 以“是否可直接支持业务”为判断标准，不以文档数量作为完成标准。

## 3.4 三种阅读路径

### 3.4.1 按角色阅读

1. 建设单位：优先阅读第4、6、7、9、15、16章。  
2. 设计单位：优先阅读第5、7、8、10、11、16章。  
3. 施工单位：优先阅读第7、8、9、10、12、16章。  
4. 运维接收单位：优先阅读第5、6、13、14、16章。  
5. 技术团队：优先阅读第10、11、12、13、14、17章。

### 3.4.2 按阶段阅读

1. 项目启动：先读第1~4章与第15章。  
2. 设计阶段：重点读第7~11章与第16章相关节。  
3. 施工阶段：重点读第8~13章与第16章相关节。  
4. 竣工移交：重点读第9、10、13、16章。  
5. 运维衔接：重点读第5、6、14、16、17章。

### 3.4.3 按任务阅读

1. 定义交付要求：读第6、7章。  
2. 组织生产协同：读第8、10章。  
3. 开展审查确认：读第9、13章。  
4. 组织移交接收：读第13、16章。  
5. 做技术实现：读第11、14、17章。

## 3.5 项目使用方法（建议流程）

建议项目团队按以下步骤使用本指南：

### 步骤1：建立项目使用清单

在项目启动会确定“本项目必用章节清单”，并对应责任角色与完成时点。

### 步骤2：形成执行文件首版

基于必用章节形成首版执行文件，至少包括：

1. 交付用途清单。  
2. 信息需求表。  
3. 命名与版本规则。  
4. 检查项清单。  
5. 样本验证记录模板。

### 步骤3：按节点开展复核

在阶段切换前，对上述文件做一次节点复核，更新变更项与责任项。

### 步骤4：把章节要求转成会议与交付动作

每次周例会、节点会应至少回答：

1. 当前交付用途是否变化。  
2. 信息需求是否有新增或删减。  
3. 交付检查发现的问题是否已处理。  
4. 下一个节点的交付准备是否完成。

建议同步记录一次“本章使用完成判定”：是否已形成项目使用清单、是否已发布执行文件首版、是否已确定节点复核机制。三项同时满足后，进入后续章节深化实施。该判定结果应进入项目周报。

## 3.6 职责与资源配置建议

### 3.6.1 职责配置

1. 建设单位：批准项目使用清单与节点计划。  
2. 总承包：组织各单位执行章节要求并汇总结果。  
3. 各参建单位：按本指南对应章节提交执行成果。  
4. 信息管理岗位：维护指南执行台账和版本记录。  
5. 技术团队：保障规则检查和数据交换工具可用。

### 3.6.2 资源配置

1. 协同平台需支持版本留痕、节点发布和权限控制。  
2. 文档模板需统一格式，便于跨单位复用。  
3. 项目应设置固定时间开展指南执行复核。  
4. 项目管理层应提供跨单位协调资源。

## 3.7 重点难点与处理建议

### 难点1：知道要做什么，但不知道先后顺序

处理建议：先用“项目使用清单”锁定优先章节，再按阶段推进。

### 难点2：章节内容理解一致，执行结果不一致

处理建议：把章节要求转成统一模板和固定检查项，减少自由解释空间。

### 难点3：技术团队与业务团队关注点不同

处理建议：在同一节点同时检查“业务可用性”和“技术可实现性”。

### 难点4：项目后期时间紧，执行动作被压缩

处理建议：把关键动作前置到启动和阶段切换节点，避免集中补做。

## 3.8 小型案例（示例）

> 说明：以下为方法演示示例，不作为项目事实引用。

某项目在启动阶段把本指南当作参考资料，没有形成项目使用清单。进入施工图阶段后，设计与施工团队对“必交项”理解不一致，导致节点前集中返工。随后项目组按本章方法处理：

1. 先确定必用章节与责任角色。  
2. 形成统一执行文件并固定更新频次。  
3. 在节点会按“用途—需求—检查—准备”四项检查。  
4. 对执行偏差建立责任追踪。

处理后，阶段交接中的争议减少，节点准备更加可控。

## 3.9 本章小结

1. 本指南应按角色、阶段、任务三条路径使用。  
2. 项目要把章节要求转成可执行文件和节点动作。  
3. 指南使用效果取决于职责落实和持续更新。  
4. 先建立使用清单，再深化技术实施，效率更高。
