# 第三章：信息组织与数据架构 (Information Organization & Data Architecture)

如果说建模软件是数字化交付的生产工具，那么信息架构就是数字化交付的“语法规则”。在缺失统一架构的情况下，模型只是几何碎片的堆砌；只有当数据被纳入严密的逻辑容器中时，它才具备被计算、被检索和被管理的价值。

本章将从空间、构件、身份与属性四个维度，解构 BIM 交付物的底层数据逻辑。

## 3.1 空间分解结构 (Spatial Breakdown Structure)

建筑本质上是物理空间的容器。在数字化交付中，我们必须首先建立一个稳健的空间骨架，以容纳数以万计的构件。

### 3.1.1 绝对的层级逻辑 (IfcProject -> IfcSite -> IfcBuilding -> IfcBuildingStorey)

无论项目多么复杂，均不得破坏 IFC 标准定义的严格包含关系。我们经常看到为了方便建模而创造的“假楼层”（例如用于放置幕墙埋件的中间层），这种做法在出图时或许有效，但在数据集成时会导致灾难性的空间错乱。

有效的交付必须保证：每一个构件都能且仅能被归属到一个特定的空间节点中。对于跨越多个楼层的垂直构件（如电梯导轨、管道立管），必须制定统一的归属规则（通常建议归属到底部起始楼层），并在 IDP 中予以明确。

### 3.1.2 空间的语义化

空间不仅仅是构件的容器，它本身就是一种资产。一个“房间” (Space/Room) 应当携带其自身的属性（如设计照度、换气次数、功能分区编码）。在交付模型中，必须创建并未被实体墙围合的“虚拟空间对象”，以便于运维阶段的空间管理系统 (FM) 直接读取。

## 3.2 构件分解结构 (Component Breakdown Structure)

构件是信息的最小载体。如何定义一个“构件”，直接决定了模型的颗粒度与可用性。

### 3.2.1 颗粒度的陷阱：系统 vs. 单体

在机电交付中，最常见的争议在于“系统”与“单体”的界限。例如，一段风管究竟是作为一个独立的资产交付，还是作为“送风系统”的一部分？

我们主张依据**可维护性**原则来划定颗粒度。对于需要单独进行维修、更换或资产折旧的对象（如风机盘管、阀门、配电箱），必须作为独立构件交付；而对于仅起连接作用的附属物（如风管直管段、电缆桥架），则建议以“系统”或“回路”为单位进行聚合管理，无需为每一节 2 米长的风管分配独立的资产编码。

### 3.2.2 分类编码 (Classification) 的双重映射

构件的命名（如 "AHU-L1-01"）往往随项目习惯而变，是不稳定的；而分类编码（如 OmniClass 或国标 GB/T 51269）则是通用的。基于 ISO 12006-2 框架的分类体系，使得计算机能够跨越命名习惯的差异，识别出“这是一台空气处理机组”。有效的交付要求每个构件都挂载至少一套标准分类码。

## 3.3 身份管理：全局唯一标识符 (GUID)

在数字孪生的世界里，GUID (Globally Unique Identifier) 是构件的身份证，其生成规则需遵循 ISO 11578 或相关 IFC 标准。它的核心价值在于**持久性 (Persistence)**。

在设计阶段，构件可能会经历位置移动、参数修改甚至类型替换，但只要它在逻辑上仍是“同一个对象”，其 GUID 就应当保持不变。这正是实现 4D 进度关联与 5D 成本关联的基础。如果每次模型导出都重新生成 GUID，下游的进度挂接与造价匹配工作将面临推倒重来的风险。因此，禁止在交付过程中随意删除并重建构件，而应优先采用“修改属性”的操作方式。

## 3.4 属性集 (Property Sets)：价值的载体

属性是数据的灵魂。为了避免“信息过载”，我们必须对属性进行分级管理。

### 3.4.1 原生属性 vs. 自定义属性

BIM 软件通常会自动生成大量几何属性（如体积、长度），这些是“原生属性”。而交付的重点在于“自定义属性” (Custom Psets)，即那些无法从几何体直接测量、但对工程管理至关重要的信息（如防火等级、传热系数、生产厂家、采购日期）。

### 3.4.2 属性的数据类型约束 (Data Templates)

“大写文本”是数据的大敌。如果要求交付“额定电压”，有人填写 "220V"，有人填写 "220 Volt"，也有人填写 "220"，这将导致数据无法被统计。

有效的交付架构必须参考 ISO 23387 定义严格的数据模板 (Data Template) 与类型约束：

- **布尔值 (Boolean)**：用于“是否承重”、“是否外露”等二元判断。
- **枚举值 (Enumeration)**：用于“防火等级”等有限选项，严禁手写输入。
- **数值 (Real/Integer)**：必须显式定义单位（如 mm, kW），确保数值可运算。

只有当属性被约束在严密的类型定义中时，BIM 模型才能从“好看的三维画”进化为“可计算的工程数据库”。
