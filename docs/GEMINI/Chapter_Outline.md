# BIM 交付指南章节大纲 (Chapter Outline)

## 第一章：核心理念 (Core Concepts)

*本章旨在阐述 BIM 交付在建筑全生命周期中的战略价值，揭示从“几何建模”向“数据资产”转型的底层逻辑。*

> **本章目标 (Goal)**: 确立以“数据资产”为核心的交付价值观，剖析 B-I-M 三者在交付语境下的真实含义。
> **非本章目标 (Boundary)**: 不涉及具体的软件操作指令或行政审批流程。

- 1.1 交付范式的转移：从“图纸”到“数字契约” (The Paradigm Shift)
- 1.2 下定义的勇气：什么是“有效”的 BIM 交付 (Defining Effective Delivery)
- 1.3 价值模型：真实性、可集成性与可维护性 (Value Model: Authenticity, Integrability, Maintainability)
- 1.4 本指南的逻辑架构与阅读指引 (Structure of this Guidance)

## 第二章：BIM 交付关键技术基础 (Key Technical Foundations)

*建立技术共识，涵盖标准体系、模型表达及数据交互的基础理论。*

> **本章目标 (Goal)**: 确立全指南通用的技术规则，包括标准引用、LOD/LOI 定义及数据格式要求。
> **非本章目标 (Boundary)**: 不重复各阶段特定的交付物清单，仅规定通用原则。

- 2.1 国内外标准体系综述 (Review of Standards)
- 2.2 模型组织、拆分与 LOD/LOI 管理 (Model Organization & Granularity)
- 2.3 数据交换标准与格式 (Exchange Formats)
- 2.4 交付物自动化质检与合规性验证 (Automated QC & Compliance)

## 第三章：信息组织 (Information Organization)

*从工程数据的无序化倾向出发，构建一套从分类、定义、元数据到主数据的完整信息组织方法论。*

> **本章目标 (Goal)**: 建立 BIM 交付物的信息组织框架，涵盖模型单元层级、身份标识、属性架构、元数据治理与主数据管理。
> **非本章目标 (Boundary)**: 不涉及特定软件的数据库实现细节，不涉及信息交付流程（见第四章）。

- 3.1 信息组织总论：工程数据为什么自发趋向无序
  - 3.1.1 工程数据的无序化倾向（框架割据、语义断层、数据冲突、数据沉没）
  - 3.1.2 从"文件交付"到"数据交付"的范式跃迁
  - 3.1.3 信息组织的四个基本层次（分类层、定义层、容器层、关联层）
- 3.2 模型单元与层级架构：自我嵌套的单元化信息集合
  - 3.2.1 模型单元的定义与自嵌套特性
  - 3.2.2 本体信息模型与业务信息模型（"一源多流"架构）
  - 3.2.3 模型单元的层级化分解（LOD 1.0–4.0）
  - 3.2.4 最小模型单元的战略选择
- 3.3 身份标识与分类编码：数字世界的"身份证"体系
  - 3.3.1 身份标识四要素（GUID、分类编码、名称、代号）
- 3.4 属性信息架构：从"数据字典"到"语义网"
  - 3.4.1 数据字典：语义互操作的基石（ISO 12006-3、bSDD）
  - 3.4.2 属性集的结构化设计
  - 3.4.3 属性深度的精细化管理（Nx）
  - 3.4.4 数据类型的严格约束
  - 3.4.5 数据模板：从"属性定义"到"结构化交付"（ISO 23387）
- 3.5 元数据：关于数据的数据
  - 3.5.1 元数据的概念起源与工程价值
  - 3.5.2 元数据的三维分类框架（描述性、管理性、结构性）
  - 3.5.3 ISO 19650 的元数据框架（命名约定、修订代码、状态代码）
  - 3.5.4 IFC 中的元数据实体（FILE_HEADER、IfcOwnerHistory、IfcDocumentInformation）
  - 3.5.5 元数据治理的工程实践
- 3.6 主数据与主数据管理：从数据治理到信息资产化
  - 3.6.1 主数据的概念与边界（主数据 vs 元数据 vs 参考数据）
  - 3.6.2 建设工程中的主数据对象
  - 3.6.3 主数据管理与 BIM 的深层关联
